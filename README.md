# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
# 处理时乱序：灌「乱序早到样例」（乙在匣未开腿）→「乱序追水位样例」（冲洗开腿）
#           →「冲洗成对并发样例」（同票仅一对）→ 到达序匣页核对匣态/冲洗时刻/开腿结果/valid
```

## 处理时乱序缓冲（到达序匣）

唯一架构口径：**以处理水位入匣为准**（站规 `乱序缓冲口径` 落档，全局贯彻，不与「事件时直配」口径混用）。

- 处理水位 = 已接纳事件最大处理时（跨批次持久化于站规 `处理水位`）。
- 刷卡满足 **处理时 < 事件时 且 事件时 > 处理水位** → 入到达序匣：刷卡点命运 `已入匣`，**入匣期间禁止开腿/成对**，开腿账/行程账无该票。
- 后续事件把处理水位抬过匣内事件时 → 按到达序（`序`）冲洗，重放同一条主链路（开腿/成对/旁路）；冲洗先翻 `匣态=已冲洗、valid=0` 再重放，重入不双配、不永久卡死。
- 到达瞬间两口径可区分：本口径下该进站 = 刷卡点`已入匣` + 有匣行 + 开腿账无腿；直配口径下不会出现任何匣行。
- 只读接口 `GET /api/到达序匣`：事件编号、匣态、冲洗时刻、开腿结果、valid（可按匣态过滤）。

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等 |
| 到达序匣 | 处理时早到、事件时仍在未来的刷卡；水位追上后冲洗开腿/成对 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运 ↔ 匣态互证 |
